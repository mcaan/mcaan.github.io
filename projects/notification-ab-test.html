Product Notification A/B Test

Testing whether an in-app notification for a new product category could increase purchases without an unacceptable rise in app uninstalls.

Decco · Course-provided experiment dataPython · SciPy · statsmodelsRandomization checks · Guardrails

View code and full README on GitHub ↗

The question

Decco, a home-decor retailer in an instructional case study, introduced a Lamps category. Would a promotional notification increase transactions—and what would it cost in app uninstalls?

100,000 users were assigned equally to treatment (notification) and control (no notification). Transaction rate was the primary metric; uninstall rate was the retention guardrail. Revenue per randomized user captured the overall monetization effect.

The approach

01

Size the experiment around a historical 10.1% transaction rate and a 20% relative minimum detectable effect, then check allocation, missingness, and baseline covariates.

02

Compare randomized groups with differences in proportions, two-proportion tests, and confidence intervals. Check the conclusions with baseline-adjusted logistic models.

03

Translate transaction, revenue, and uninstall effects to a common scale of 10,000 treated users; treat post-hoc subgroup findings as hypotheses for another experiment.

What happened

The notification increased transaction rate from 10.12% to 17.52%, an absolute lift of 7.40 percentage points (95% confidence interval: approximately +6.98 to +7.83 points). Revenue per randomized user increased from $27.51 to $56.67.

The guardrail also worsened: uninstall rate rose from 2.99% to 5.03%, approximately +2.03 percentage points. The same treatment that drove purchases was associated with more users removing the app.

The product decision

For every 10,000 users exposed at the observed effects, the experiment implies roughly 740 additional purchasers, $291,581 more revenue, and 203 additional uninstalls. These figures make the trade-off concrete but do not by themselves establish whether the lost users outweigh the incremental sales.

The recommendation is not to roll out this version broadly. Instead, test alternative message, timing, frequency, or targeting choices to preserve purchase lift while reducing uninstall risk. A break-even decision needs contribution margin and the expected future value lost when a user uninstalls.

What to validate next

An exploratory analysis found a larger uninstall effect among previously active users (+2.51 points) than inactive users (+0.60 points), with an interaction p-value of 0.009. Because this comparison was motivated after seeing the results, it is a hypothesis for a pre-specified follow-up test, not a ready-made targeting policy.

Allocation was exactly 50/50, and observed baseline characteristics were similar, but those checks cannot prove every aspect of implementation was error-free. The data come from instructional course material, not a live operating retailer.
